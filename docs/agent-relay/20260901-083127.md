# Safer widget updates and compatible page overlays

## What changed

- Explicit `nil` values now clear pluggable-widget properties according to their schema type. Known types reset to their default or empty representation; unknown types fail with `ValidationError`.
- Nested pluggable-widget objects now reuse existing object and property identities by position. Only appended objects receive new identities, and corrupt type pointers fail closed.
- DataView overlays now support `no_entity_message`. Structural fingerprints are versioned: existing version 1 exports are verified with the original algorithm, while new exports use version 2.

## Why

These changes make repeated writes stable, allow intentional property clearing, and prevent an mxrb upgrade from falsely reporting structural drift on previously exported DataView pages.

## Usage and compatibility

Pass `nil` to clear a supported pluggable-widget property, and set `no_entity_message:` normally on newly exported DataViews. Legacy version 1 pages continue to regenerate unchanged, but must be re-exported to version 2 before editing `no_entity_message`. Unknown metadata versions and unsafe projections are rejected rather than guessed.
