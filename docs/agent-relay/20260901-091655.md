# MPR v2 integrity and safe widget-object reconciliation

## What changed

- MPR schemas that store unit contents externally now require the sibling `mprcontents/` directory. Missing package data raises `Mxrb::IncompletePackageError` instead of being misread as an empty v1 project.
- `MprFile#backup!` and `#restore_from!` now snapshot and reconcile all v2 `.mxunit` files as well as SQLite state. Modified and deleted files are restored, inserted orphans are removed, and incomplete v2 backups fail closed. V1 remains SQLite-only.
- `MprFile#cleanup_backup!` removes both backup artifacts, and `BatchPlan` uses it so failed v2 batches roll back cleanly without leaking snapshots.
- Nested pluggable-widget objects still reuse identities by position and create identities for appends, but shrinking the array now raises `Mxrb::ValidationError` because removed identities cannot be matched safely.

## Why

This prevents partial v2 packages and failed batches from producing silently incomplete or misleading project state. It also avoids assigning surviving widget configurations to the wrong existing object when an array shrinks.

## Usage

Existing `BatchPlan` usage needs no changes. Direct backup callers should pair `mpr.backup!(path)` with `mpr.restore_from!(path)` when needed and `mpr.cleanup_backup!(path)` afterward. Widget-object arrays may keep their size, edit values in place, reorder by position, or append items; reducing the item count is intentionally rejected.
