# Atomic MPR backup and restore

## What changed

- `restore_from!` now validates a backup's SQLite schema and required v2 `.mprcontents` snapshot before changing the live project.
- V2 restores recreate a missing live `mprcontents/` directory from the backup snapshot.
- `backup!` removes stale destination artifacts before starting and removes partial SQLite and snapshot files if any backup step fails.
- V1 backups remain single-file SQLite backups.

## Why

Invalid or incomplete backups now fail without closing or modifying the live project, while backup failures no longer leave artifacts that a later restore could mistake for a complete backup.

## Usage

The API is unchanged: use `backup!(path)`, `restore_from!(path)`, and `cleanup_backup!(path)` as before. A v2 backup consists of both `path` and `path.mprcontents`; keep them together when copying or retaining backups.
