# Eloquent REST services and safer project writes

## What changed

- Published REST services now support a block DSL with nested `resource` and HTTP-operation declarations. Parameters and JSON/export mappings are inferred from the target microflows, generated routes include the resource path, and the existing `resources:` form remains supported.
- Ruby-app controllers now translate model attributes for native calls and return `404 not_found` for missing records, enabling conventional CRUD services over public attributes such as an `AutoNumber` identifier.
- `long` now maps consistently to Mendix's native integer type, and repeated writes deduplicate nested parameter identities.
- BSON output places `$ID` before `$Type` when an identity exists, with validation for missing, duplicate, or misordered nested identities.
- V2 MPR backup and restore now treat SQLite plus `mprcontents/` as one package: incomplete snapshots fail closed, restores recreate deleted content and remove orphans, and failed batches clean up both artifacts.
- Page and widget overlays support typed `nil` clearing, preserve reusable nested-object identities, reject unsafe array shrinking, and use versioned structural fingerprints without invalidating version 1 baselines.

## Why

The change makes REST APIs concise to declare and executable in the Ruby runtime while keeping generated projects deterministic, round-trippable, and recoverable after partial or repeated writes.

## Usage

```ruby
published_rest_service :ItemsApi, path: 'api', version: '1.0' do
  resource :items do
    get :show, path: '{id}', microflow: 'Catalog.ShowItem'
    post :create, path: '', microflow: 'Catalog.CreateItem',
                  success_status: :created
  end
end
```

Define the microflow signatures normally; mxrb derives REST parameters and mappings. Existing hash-based `resources:` declarations need no migration. Keep a v2 backup's database file and its `.mprcontents` snapshot together, and append or update widget-object arrays without reducing their length.
